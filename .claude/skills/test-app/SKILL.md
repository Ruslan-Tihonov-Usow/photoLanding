# Тестирование landingPhoto

E2E-проверка Nuxt-приложения в браузере через Playwright MCP. Использовать после
UI-изменений или по прямому запросу «протестируй приложение».

## Требования

- MCP-сервер `playwright` должен быть подключён (см. `~/.claude.json` → `mcpServers.playwright`).
- Node.js должен быть доступен в PATH текущей команды:
  `$env:Path = "C:\Program Files\nodejs;" + $env:Path` перед любой npm/npx-командой (PowerShell).

## Шаг 1 — поднять dev-сервер

```powershell
$env:Path = "C:\Program Files\nodejs;" + $env:Path
cd "c:\IT\landingPhoto"
npm run dev
```

Запускать в фоне (`run_in_background: true`), т.к. процесс не завершается сам.
Дождаться в логе строки вида `Local: http://localhost:3000/` перед тем как открывать
браузер. Если порт 3000 занят — Nuxt сам возьмёт следующий свободный (3001, 3002…),
проверить фактический адрес в выводе.

## Шаг 2 — обойти все страницы

Маршруты приложения:
- `/` — главная (Hero + избранные проекты)
- `/portfolio` — портфолио (баннер + галерея категорий)
- `/about` — обо мне
- `/prices` — цены (3 тарифа + CTA-секция)
- `/contacts` — контакты (форма)

Для каждой страницы через Playwright MCP:
1. `browser_navigate` на адрес страницы.
2. `browser_snapshot` — убедиться, что структура страницы соответствует ожиданиям
   (шапка `TheHeader`, контент страницы, подвал `TheFooter`), нет пустого экрана
   или страницы ошибки.
3. `browser_console_messages` — проверить, что нет записей уровня `error`
   (предупреждения от Vite HMR в dev-режиме — не ошибка, их игнорировать).
4. При необходимости `browser_take_screenshot` — как визуальное доказательство.

## Шаг 3 — проверить интерактивные сценарии

**Мобильное меню (`TheHeader.vue`)**
1. Сжать вьюпорт (`browser_resize`, например 375×800).
2. Кликнуть по бургер-кнопке (`aria-label="Открыть меню"`).
3. Убедиться, что появился список ссылок и кнопка «Записаться».
4. Кликнуть по ссылке — меню должно закрыться, произойти переход.

**Модалка бронирования (`BookingModal.vue` + `BookingButton.vue`)**
1. На любой странице кликнуть кнопку «Забронировать дату» / «Записаться».
2. Убедиться, что модалка открылась (заголовок «Забронировать дату»), фон
   заблокирован под `bg-stone-900/60`.
3. Заполнить обязательные поля (Имя, Email) и отправить форму.
4. Убедиться, что вместо формы показалось сообщение «Спасибо! Заявка отправлена…».
5. Закрыть через кнопку × — модалка должна исчезнуть.
6. Повторно открыть и закрыть через `Escape` — тоже должна закрыться
   (`onKeydown` в `useBookingModal`).
7. Повторно открыть и кликнуть по тёмному фону вне карточки — тоже должна закрыться.

**Форма контактов (`pages/contacts.vue`)**
1. Перейти на `/contacts`.
2. Заполнить обязательные поля (Имя, Email, Тип съёмки, Дата события), отправить.
3. Убедиться, что вместо формы показалось сообщение об успешной отправке.

Форма ничего никуда не отправляет по-настоящему (TODO в коде: `handleSubmit`
только выставляет `isSubmitted = true`) — это ожидаемое поведение, не баг.

## Шаг 4 — итог

Собрать краткий отчёт:
- какие страницы открылись без ошибок консоли;
- какие интерактивные сценарии прошли/не прошли;
- скриншоты или тексты ошибок для найденных проблем.

Если нашлась поломка — не чинить молча, сначала показать пользователю, что именно
сломано (сообщение консоли / скриншот / шаг воспроизведения).

## Шаг 5 — остановить dev-сервер

Если сервер запускался в этом шаге (не был поднят пользователем заранее) —
остановить фоновый процесс после завершения проверки, чтобы не оставлять
висящий node-процесс и занятый порт.
