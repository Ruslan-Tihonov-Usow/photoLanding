# Инструкции для агента

## 1. Соблюдай контекст
- Держи в голове текущий проект и активные файлы.
- Не меняй то, что не относится к задаче.

## 2. Пиши понятные инструкции
- Если предлагаешь изменение — объясняй, зачем и что именно.
- Используй простой язык и короткие фразы.

## 3. Проверяй перед изменением
- Сначала изучи файлы/структуру проекта.
- Только после этого редактируй.

## 4. Будь осторожен с изменениями
- Не ломай существующий код.
- При значительных правках предлагай backup / пошаговый план (step-by-step).

## 5. Приоритизируй безопасность
- Не вставляй секреты или приватные данные.
- Не используй внешние ресурсы без необходимости.

## 6. Оставляй полезные комментарии
- Если меняешь код — поясни, что исправлено.
- Если предлагаешь команду — укажи результат и последствия.

## 7. Сохраняй формат ответа
- Используй заголовки, списки, короткие абзацы.
- Если нужно — добавляй примеры команд или краткий план.

## 8. Декомпозиция компонентов
- Не создавай большие сложные компоненты объёмом свыше **500 строк**.
- Если компонент разрастается — выноси части в дочерние компоненты, композаблы (`composables/`) или утилиты (`utils/`).

## 9. Синтаксис внутри компонента (Vue SFC)
Порядок блоков в `.vue`-файле всегда фиксированный:
1. `<template>` — вёрстка
2. `<script setup>` — логика
3. `<style>` — стили (только если они действительно нужны)

```vue
<template>
  <!-- вёрстка -->
</template>

<script setup lang="ts">
// логика
</script>

<style scoped lang="scss">
/* стили, если нужны */
</style>
```

## 10. Стили
- Основной инструмент — **Tailwind CSS**.
- Если Tailwind не покрывает задачу — использовать **SCSS** с методологией **БЭМ** (`block__element--modifier`).
- Не смешивать произвольный inline-CSS с Tailwind без необходимости.
